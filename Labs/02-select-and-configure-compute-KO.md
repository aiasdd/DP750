# 랩 02: Azure Databricks에서 컴퓨팅 선택 및 구성

이 랩에서는 **HealthBridge Analytics**의 데이터 엔지니어로 일합니다. HealthBridge Analytics는 병원 입원, 실험실 결과, 청구 및 규정 준수 데이터에 이르기까지 매일 수백만 개의 환자 기록을 처리하는 지역 의료 조직입니다. 귀사의 팀은 Azure Databricks를 사용하여 데이터 엔지니어링 파이프라인, 임시 분석 및 파이프라인 검증 워크로드를 실행합니다.

귀사의 팀이 데이터를 처리하기 전에 적절한 컴퓨팅 리소스가 구성되어 있는지 확인해야 합니다: 대화형 개발용 조정된 클러스터 및 노트북에 필요한 종속성이 있도록 적절히 설치된 라이브러리입니다.

이 랩을 완료하면 다음을 수행할 수 있습니다:

- 적절한 성능 설정, Databricks Runtime 및 Photon 가속화를 사용하여 다목적 클러스터를 생성하고 구성합니다.
- Databricks UI를 통해 클러스터 범위 라이브러리를 설치합니다.
- `%pip install`을 사용하여 노트북 범위 라이브러리를 설치하고 설치를 확인합니다.
- 설치된 라이브러리를 사용하여 합성 환자 데이터를 생성하고 분석합니다.

이 랩은 완료하는 데 약 **30분**이 소요됩니다.

## 연습 1: 다목적 클러스터 생성 및 구성

HealthBridge의 데이터 엔지니어링 팀은 대화형 개발용 공유 클러스터가 필요합니다. 귀사의 작업은 의료 분석 워크로드 협업에 적합한 설정으로 이 클러스터를 생성하고 구성하는 것입니다.

### 작업 1.1: 새 다목적 클러스터 생성

1. 왼쪽 사이드바에서 **컴퓨팅**을 선택합니다.
2. **컴퓨팅 생성**을 선택합니다.
3. **간단한 양식** 드롭다운을 **끔**으로 설정합니다.
4. 클러스터 생성 양식에서 다음을 설정합니다:

    | 설정          | 값              |
    | ---------------- | ------------------ |
    | **클러스터 이름** | `healthbridge-dev` |
    | **정책**       | 제한 없음       |
    | **클러스터 모드** | 다중 노드         |
    | **액세스 모드**  | 공유             |

5. **생성**을 선택하지 **마세요** — 아래의 설정을 계속합니다.

### 작업 1.2: 성능 및 런타임 설정 구성

여전히 클러스터 생성 양식에서:

1. **Databricks Runtime 버전** 아래에서 **최신 LTS(장기 지원)** 버전을 선택합니다.

    > **팁:** LTS 버전은 공유 팀 클러스터에 권장됩니다. LTS 버전은 확장 지원을 받으며 LTS가 아닌 버전보다 더 안정적이기 때문입니다.

2. **워커 유형** 아래에서 **메모리에 최적화된** 인스턴스(예: **E 시리즈** VM)를 선택합니다. 의료 분석 워크로드에는 환자 기록과 실험실 결과 테이블 간의 대규모 조인이 포함되는 경우가 많으며, 이는 메모리 대 코어 비율이 높을 때 이점이 있습니다.

3. **워커** 아래에서 **자동 크기 조정**을 사용하도록 설정하고 다음을 설정합니다:
    - 최소 워커: `1`
    - 최대 워커: `3`

4. **자동 종료** 아래에서 사용으로 설정하고 제한 시간을 **15분**으로 설정합니다.

    > **왜 15분인가요?** 이렇게 하면 분석 세션 간에 클러스터가 유휴 상태로 유지되지 않으므로 엄격한 예산 거버넌스가 있는 의료 조직의 비용 제어에 중요합니다.

5. 위로 스크롤하여 **Photon 가속화**가 **사용**으로 설정되어 있는지 확인합니다.

6. **컴퓨팅 생성**을 선택합니다.

계속하기 전에 클러스터가 **실행 중** 상태에 도달할 때까지 기다립니다. 이는 몇 분이 걸릴 수 있습니다.

## 연습 2: 클러스터 범위 라이브러리 설치

귀사의 팀은 *faker* 라이브러리를 사용하여 파이프라인 테스트용 합성 환자 데이터셋을 생성합니다. healthbridge-dev 클러스터에서 실행되는 모든 노트북에서 이 라이브러리를 사용할 수 있도록 해야 합니다.

[faker](https://faker.readthedocs.io/)는 테스트, 프로토타이핑 및 데이터베이스 시딩에 사용할 이름, 주소, 전화 번호, 날짜 등과 같은 현실적인 가짜 데이터를 생성하는 Python 라이브러리입니다. 많은 로케일 및 데이터 범주를 지원하므로 실제 개인 정보를 사용하지 않고도 대량의 그럴듯한 합성 데이터를 쉽게 생성할 수 있습니다.

### 작업 2.1: faker를 클러스터 범위 라이브러리로 설치

1. **컴퓨팅** 페이지에서 healthbridge-dev 클러스터를 선택합니다.
2. **라이브러리** 탭을 선택합니다.
3. **새로 설치**를 선택합니다.
4. 다음을 설정합니다:

    | 설정            | 값           |
    | ------------------ | --------------- |
    | **라이브러리 소스** | PyPI            |
    | **패키지**        | `faker==40.8.0` |

    > **왜 버전을 고정하나요?** 의료 데이터 엔지니어링 환경에서는 재현성이 중요합니다. *faker*의 정확한 버전을 고정하면 모든 팀 구성원과 모든 파이프라인 실행이 동일한 라이브러리를 사용하여 업스트림 버전 변경으로 인한 예기치 않은 동작을 방지합니다.

5. **설치**를 선택합니다.

6. 라이브러리 폭 탭에서 라이브러리 상태가 **설치됨**으로 표시될 때까지 기다립니다.

    > **참고:** 클러스터 범위 라이브러리는 클러스터가 다시 시작될 때마다 자동으로 다시 설치됩니다. 이렇게 하면 수동 개입 없이 환경이 일관성 있게 유지됩니다.

## 클러스터 중지 또는 삭제

클러스터 구성 및 라이브러리 설치를 살펴봤으므로 **healthbridge-dev** 클러스터는 더 이상 나머지 연습에 필요하지 않습니다. 불필요한 컴퓨팅 비용을 피하려면 계속하기 전에 이를 중지하거나 삭제하세요.

1. 왼쪽 사이드바에서 **컴퓨팅**을 선택합니다.
2. **healthbridge-dev** 클러스터를 선택합니다.
3. **종료**를 선택하여 클러스터를 중지하거나 **⋮** 메뉴를 선택한 다음 **삭제**를 선택하여 완전히 제거합니다.

    > **참고:** 나머지 연습은 **서버리스** 컴퓨팅에서 실행되므로 클러스터를 안전하게 삭제할 수 있습니다. 삭제하면 실수로 다시 시작되어 추가 비용이 발생하는 것을 방지할 수 있습니다.

## 연습 3: 노트북에서 라이브러리 작업

클러스터가 구성되었으므로 노트북으로 전환하여 나머지 코드 기반 연습을 완료합니다.

### 노트북을 서버리스 컴퓨팅에 연결

1. 앞에서 가져온 **02-select-and-configure-compute** 노트북을 엽니다.
2. 노트북 위쪽의 컴퓨팅 선택기에서 **서버리스** 컴퓨팅을 선택합니다.

    > **참고:** 노트북의 연습 3과 4는 **서버리스** 컴퓨팅을 사용합니다. 연습 1에서 생성한 클러스터는 컴퓨팅 구성 이해와 관련이 있습니다(노트북 자체는 서버리스에서 실행되어 클러스터 범위 라이브러리와 독립적으로 작동하는 노트북 범위 라이브러리 설치를 시연합니다).

3. 노트북 내의 연습을 계속합니다.
