# 랩 11: Azure Databricks로 Lakeflow 작업 구현

## 소개

귀사는 매일 수백만 통의 전화, SMS 메시지 및 데이터 세션을 관리하는 지역 통신 제공자인 **TelConnect**의 데이터 엔지니어입니다. 각 이벤트는 **CDR(호출 상세 기록)** — 네트워크 활동의 원본 신호를 생성합니다. 운영 팀이 네트워크 성능 보고 및 용량 계획에 사용하기 전에 이 데이터는 다층 파이프라인을 통해 안정적으로 흘러야 합니다.

오늘의 작업은 **Lakeflow 작업**을 사용하여 해당 파이프라인을 자동화하는 것입니다. 귀사는:

- CDR 데이터를 처리하는 사전 구축 매개변수화 **메달리온 아키텍처** 노트북(Bronze → Silver → Gold)을 실행합니다
- Azure Databricks UI에서 **Lakeflow 작업**을 생성하여 노트북을 오케스트레이션된 작업으로 실행합니다
- 동적 트리거 값을 사용하여 `processing_date` **작업 매개변수**를 노트북에 전달합니다
- **작업 종속성**이 있는 두 번째 다운스트림 작업을 추가합니다
- 새 CDR 파일이 볼륨에 도착할 때 실행되는 **이벤트 기반 파일 도착 트리거**를 구성합니다
- 매일 밤 자동으로 작업이 실행되도록 **야간 cron 일정**을 추가합니다
- **실패 알림**을 설정하여 네트워크 운영 팀이 즉시 알림을 받도록 합니다
- 일시적인 클라우드 저장소 오류를 처리하기 위해 **자동 재시도 정책**을 구성합니다

## 파트 2: Lakeflow 작업으로 오케스트레이션(UI 연습)

이러한 연습은 이 랩의 핵심입니다. Azure Databricks **작업 및 파이프라인** UI를 사용하여 방금 실행한 노트북을 트리거, 일정, 알림 및 재시도 정책이 있는 프로덕션 등급 자동화 작업으로 연결합니다.

### 연습 1: CDR 파이프라인 노트북을 사용하여 Lakeflow 작업 생성

#### 작업 생성

1. 왼쪽 사이드바에서 **작업 및 파이프라인**을 클릭합니다.
2. **작업 생성**을 클릭합니다.
3. 기본 작업 이름을 `TelConnect CDR Pipeline`으로 바꿉니다.

#### 첫 번째 작업 구성

4. 작업 편집기에서 작업 이름 `process_cdrs`를 입력합니다.
5. **유형** 드롭다운에서 **노트북**을 선택합니다.
6. **소스** 드롭다운에서 **작업 영역**을 선택한 다음 가져온 노트북의 경로(*11-implement-lakeflow-jobs*)로 이동합니다.
7. **컴퓨팅** 선택기에서 **서버리스**를 선택합니다.
8. **작업 저장**을 클릭합니다.

#### 작업 매개변수 추가

9. 오른쪽의 **작업 세부 정보** 패널에서 **매개변수** 섹션으로 스크롤하고 **추가**를 클릭합니다.
10. 키를 `processing_date`로 설정하고 값을 `{{job.trigger.time.iso_date}}`로 설정합니다.

   > 이 동적 값은 작업이 트리거된 날짜를 삽입하여 노트북의 위젯 기본값과 일치합니다.

11. 매개변수에서 **저장**을 클릭합니다.

#### 확인

12. 작업 그래프에서 **process_cdrs**가 단일 노드로 표시되는지 확인합니다.
13. **지금 실행**을 클릭하여 작업을 수동으로 테스트합니다.
14. **실행** 탭에서 실행이 완료될 때까지 기다리고 모든 노트북 셀이 성공적으로 실행되었는지 확인합니다.

---

### 연습 2: 다운스트림 알림 작업 추가

실제 파이프라인에서는 CDR 처리 작업이 완료된 후 요약 보고서를 보내는 두 번째 작업을 원할 수 있습니다. 여기서는 Gold 테이블에서 읽는 짧은 SQL 작업으로 이를 시뮬레이션합니다.

1. **TelConnect CDR Pipeline** 작업 편집기에서 **process_cdrs** 아래의 **+ 작업 추가**를 클릭합니다.
2. 작업 이름 `summarize_gold`로 지정합니다.
3. **유형** 드롭다운에서 **SQL**을 선택합니다.
4. **SQL** 필드에서 다음을 입력합니다:

   ```sql
   SELECT region, network_type, total_calls, drop_rate_pct
   FROM telconnect_lab.gold.network_summary
   ORDER BY drop_rate_pct DESC;
   ```

5. **SQL 웨어하우스** 선택기에서 사용 가능한 서버리스 SQL 웨어하우스를 선택합니다.
6. **종속**이 이미 **process_cdrs**로 설정되어 있고 **실행 조건**이 **모두 성공**으로 설정되어 있는지 확인합니다.
7. **작업 저장**을 클릭합니다.

#### DAG 확인

8. DAG 보기를 검토합니다. 다음이 표시되어야 합니다:
   ```
   process_cdrs → summarize_gold
   ```

### 연습 3: 파일 도착 트리거 구성

TelConnect는 하루 종일 불규칙적인 간격으로 신선한 CDR 파일을 볼륨에 드롭합니다. 고정 일정에서 폴링하는 대신 새 파일이 도착할 때마다 작업이 자동으로 실행되도록 구성합니다.

1. **작업 세부 정보** 패널에서 **일정 및 트리거** 아래의 **트리거 추가**를 클릭합니다.
2. **트리거 유형** 드롭다운에서 **파일 도착**을 선택합니다.
3. **저장소 위치** 필드에서 다음을 입력합니다:

   ```
   /Volumes/telconnect_lab/bronze/raw_uploads/
   ```

4. **고급 옵션** 아래에서 **마지막 변경 후 대기**를 `60`초로 설정합니다.

   > 이는 빠른 파일 도착을 단일 작업 실행으로 일괄 처리합니다 — 여러 CDR 배치가 빠르게 연속으로 도착할 때 유용합니다.

5. **저장**을 클릭합니다.

#### 트리거 일시 중지

다음 연습에서 일정을 추가하기도 하므로 파일 도착 트리거를 일시 중지하여 랩 중 중복 실행을 방지합니다:

6. **일정 및 트리거** 아래에서 파일 도착 트리거를 찾고 **일시 중지**를 클릭합니다.

> **참고:** 프로덕션에서는 둘 다 활성 상태로 유지합니다 — 파일 도착 트리거는 당일 업데이트를 처리하고 일정은 안정적인 야간 포괄 실행을 제공합니다.

---

### 연습 4: 야간 일정 추가

TelConnect의 운영 팀은 아침 교대가 시작되기 전에 대시보드가 최신 상태가 되도록 매일 밤 02:00 CET에 Gold 요약 테이블이 새로 고쳐질 것으로 예상합니다.

1. **작업 세부 정보** 패널에서 **트리거 추가**를 다시 클릭합니다.
2. **트리거 유형**을 **예약됨**으로 설정합니다.
3. **일정 유형**을 **고급**으로 설정합니다.
4. **Cron 표현식** 필드에서 다음을 입력합니다:

   ```
   0 0 2 * * ?
   ```

   > 이 표현식의 의미: 초 0, 분 0, 시간 2, 매월 매일, 매월, 주중 어느 날이든.

5. **시간대**를 **Europe/Amsterdam**으로 설정합니다.
6. **저장**을 클릭합니다.

#### Cron 표현식 확인

7. 저장 후 사람이 읽을 수 있는 일정 미리 보기를 검토합니다. "매일 암스테르담 시간 오전 2:00에"라고 표시되어야 합니다.

---

### 연습 5: 실패 알림 구성

네트워크 운영 팀이 CDR 파이프라인 실패 시 즉시 알림을 받아야 합니다 — 놓친 실행은 결함 탐지 및 네트워크 SLA 보고를 지연시킬 수 있습니다.

#### 작업 수준 실패 알림 추가

1. **작업 세부 정보** 패널에서 **작업 알림**으로 스크롤하고 **알림 편집**을 클릭합니다.
2. **알림 추가**를 클릭합니다.
3. **이메일 주소**를 선택하고 이메일을 입력합니다.
4. **실패** 이벤트 유형을 선택합니다.
5. 선택적으로 **지속 시간 경고**를 선택하고 임계값을 `30`분으로 설정합니다.
6. **저장**을 클릭합니다.

#### 작업 수준 재시도 알림 추가

7. 작업 그래프에서 **process_cdrs** 작업을 선택하여 구성을 엽니다.
8. 작업 패널에서 **알림**으로 스크롤하고 **추가**를 클릭합니다.
9. **이메일 주소**(동일한 주소)를 선택하고 **실패**를 선택한 다음 **마지막 재시도까지 알림 음소거**를 확인합니다.

   > 이렇게 하면 작업이 다시 시도될 때 알림 스팸이 방지됩니다. 모든 재시도 시도가 실패한 경우에만 경고를 받습니다.

10. **작업 저장**을 클릭합니다.

---

### 연습 6: 자동 재시도 구성

CDR 파일은 클라우드 저장소에서 읽으며 일시적인 네트워크 오류나 저장소 제한은 단기 작업 실패의 일반적인 원인입니다. 재시도를 구성하면 파이프라인이 수동 개입 없이 복구됩니다.

#### process_cdrs에서 작업 수준 재시도 구성

1. 작업 그래프에서 **process_cdrs** 작업을 선택합니다.
2. 작업 구성 패널에서 **재시도** 옆의 **+ 추가**를 클릭합니다.
3. **재시도 횟수**를 `2`로 설정합니다.
4. **재시도 간격**을 `60`초로 설정합니다.
5. **작업 저장**을 클릭합니다.

#### 시간 제한 임계값 구성

6. 동일한 작업 구성에서 **메트릭 임계값**을 클릭합니다.
7. **메트릭**을 **실행 기간**으로 설정합니다.
8. **경고**를 `20`분으로 설정합니다.
9. **시간 제한**을 `30`분으로 설정합니다.
10. **작업 저장**을 클릭합니다.

> 노트북이 중단되면(예: 쿼리가 큰 CDR 백로그에 정지) 시간 제한을 사용하면 작업이 정상적으로 실패하여 작업이 무기한 실행되는 대신 재시도 메커니즘이 시작될 수 있습니다.

---

### 연습 7: 완전한 작업 실행 및 모니터링

1. **TelConnect CDR Pipeline** 작업 편집기에서 **지금 실행**을 클릭합니다.
2. **실행** 탭으로 이동하고 활성 실행을 클릭하여 실행 세부 정보를 엽니다.
3. 두 작업(process_cdrs 및 summarize_gold)이 순차적으로 실행되는 것을 관찰합니다.
4. 실행 타임라인에서 **process_cdrs**를 클릭하여 다음을 봅니다:
   - 노트북 출력(각 셀 결과)
   - 전달된 작업 매개변수 값(processing_date)
   - dbutils.jobs.taskValues.set()에서 설정한 작업 값
5. 두 작업이 완료되면 실행 상태가 **성공**인지 확인합니다.

## 요약

이 랩에서 귀사는:

- Unity Catalog에서 TelConnect CDR 데이터에 대한 **메달리온 아키텍처** 파이프라인(Bronze → Silver → Gold)을 실행했습니다
- 두 작업 및 순차적 작업 종속성을 사용하여 **Lakeflow 작업**을 생성했습니다
- 트리거 시간에 연결된 동적 작업 매개변수로 processing_date를 **매개변수로 전달**했습니다
- 새 CDR 파일이 볼륨에 도착할 때 실행되는 **파일 도착 트리거**를 구성했습니다
- 일일 새로 고침을 보장하기 위해 02:00 CET에 **야간 cron 일정**을 추가했습니다
- 재시도 경고를 음소거하여 경고 소음을 줄이기 위해 **실패 알림**을 설정했습니다
- 일시적인 클라우드 저장소 오류를 처리하기 위해 **작업 수준 재시도**(2회 시도, 60초 간격) 및 30분 시간 제한 임계값을 구성했습니다
